# «Серп на крыше» — данные для диагностики

Справка для внешней проверки. **Секреты сюда не выписаны** — где их взять, указано ниже.

## ✅ РЕШЕНО 31.07.2026 — переезд на другой сервер

Причина: **адрес 185.50.203.112 (Cloud.ru) не доходил из сети заведения** — через VPN всё работало, напрямую нет. С этого же сервера ранее был заблокирован Telegram по IP.

Решение: проект перенесён на сервер **109.122.197.207 (Frankfurt)**, A-запись `serp.stambul42.ru` переключена туда. Данные, сотрудники, журнал и история перенесены целиком. Старый сервис на Cloud.ru остановлен и снят с автозапуска.

## Проблема, которую искали

На iPad (iPadOS 17) не открываются **все** сайты с сервера 185.50.203.112 — и `serp.stambul42.ru`, и `light.stambul42.ru`.
Другие сайты (Яндекс и пр.) открываются. На телефоне те же адреса открываются нормально.
Через мобильный модем на планшете — тоже открывается. Периодически открывалось и снова переставало.

Первая гипотеза: **iCloud Private Relay / «Ограничить отслеживание IP-адреса»** на iPad — трафик идёт через Apple и не доходит до российского хостинга.
Вторая: DNS сети заведения не резолвит зону `stambul42.ru`.

## Что уже проверено — и оказалось в порядке

- Сервер отвечает 200 на `/`, `/pult/`, `/api/config`, `/health`; ответ из Яндекс.Облака — 45 мс.
- Нагрузка сервера: load average 0.02, память 3 ГБ свободно.
- DNS резолвится одинаково через 8.8.8.8, 77.88.8.8, 1.1.1.1 → 185.50.203.112.
- Сертификат Let's Encrypt действителен до 28.10.2026, TLS 1.2 и 1.3 работают.
- В логах nginx нет отказов: только коды 200, ни одного 403/429/5xx (кроме одного ожидаемого 403).
- Нет никаких блокировок: `iptables` пуст, `ufw` выключен, `fail2ban` следит только за `sshd` и `torrserver-auth`.
- **Запросов с планшета в логах нет вообще** — то есть он не доходит до сервера, а не получает ошибку.
- Ограничения приложения (лимиты вызовов, баны) отключены: `"limits": false` в `config.json`.

## Особенность сертификата (возможная зацепка)

Сертификат **ECDSA**, цепочка: `CN=serp.stambul42.ru` → `Let's Encrypt YE2` → `ISRG Root YE` → `ISRG Root X2` → `ISRG Root X1`.
На старых устройствах корень ISRG Root X2 может отсутствовать. Для iPadOS 17 это не должно быть проблемой, но при желании сертификат перевыпускается как RSA:

```
sudo certbot certonly --nginx --key-type rsa --force-renewal -d serp.stambul42.ru
sudo systemctl reload nginx
```

## Команды для проверки

```bash
# состояние приложения
ssh germany 'systemctl status serp; curl -s localhost:8906/health'

# живой лог: вызовы, входы, ошибки
ssh germany 'sudo journalctl -u serp -f'

# кто и с каким кодом ходил на сайт
ssh germany "sudo tail -2000 /var/log/nginx/access.log | grep '/pult/' | awk '{print \$1, \$9}' | sort | uniq -c | sort -rn"

# ошибки nginx (в т.ч. TLS-рукопожатия)
ssh germany 'sudo tail -50 /var/log/nginx/error.log'

# доступность и сертификат снаружи
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://serp.stambul42.ru/health
echo | openssl s_client -connect serp.stambul42.ru:443 -servername serp.stambul42.ru 2>/dev/null | openssl x509 -noout -dates -issuer
```

## Диагностика прямо с проблемного устройства

Открыть на планшете: **`https://serp.stambul42.ru/pult/diag.html`**
Страница написана без современного синтаксиса и открывается даже там, где основной пульт падает. Показывает: версию браузера, наличие сети, поддержку возможностей, установленные service worker и кэши, время ответа сервера. Там же кнопка «Сбросить кэш приложения и перезапустить».

## Что стоит проверить внешнему специалисту

1. **Private Relay / «Ограничить отслеживание IP-адреса» на iPad** — выключить и повторить (главная гипотеза).
2. Открыть на планшете `https://185.50.203.112/` (отдаст 302 — но это докажет, что до сервера по IP есть связь) — если нет, режется маршрут или DNS.
3. Сравнить поведение на мобильном интернете и на Wi-Fi заведения — если разница есть, копать в сторону DNS/фильтрации у провайдера заведения.
4. Проверить, нет ли на планшете профиля конфигурации, VPN или DNS-over-HTTPS (Настройки → Основные → VPN и управление устройством).
